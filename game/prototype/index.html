术语表

同一个词在三种语言里必须只有一个写法。术语表是 LQA 的第一道防线。

0 个术语
为什么术语表重要？ 「灵石」在英文里如果同时出现 Spirit Stone / Immortal Stone / Soul Stone，玩家会以为是三种道具。原型用术语表做一致性检查；生产版可以由 LLM 从项目里自动抽取术语候选。

原始数据

长表格式：key, locale, source, target, maxLen, context。可直接替换成你的项目导出。

0 行
01

确定性检查

占位符、富文本标签、空值、长度上限、数字、标点、空格。规则能覆盖 LQA 里最容易漏、也最不该漏的一层。

02

术语一致性

拿术语表逐条比对：源文出现术语时，目标语言必须命中指定译法；同一术语的变体会被标出来。

03

长度模型

按 UI 的 maxLen 判断溢出；没有 maxLen 时用源文长度比例做预警。英文通常比中文长 1.3–1.8 倍，日韩更长。

04

中文残留

英文/韩文里出现汉字、日文里出现简体中文游戏词（修仙/灵石/宗门），通常意味着漏译或直接复制了源文。

原型的边界：这里没有调用大模型，所以不会判断「这句翻译是否地道」。它做的是提审前必须清零的机械错误——把人的时间留给语气、文化、角色口吻这些真正需要判断的部分。
想接自己的项目？
导出 CSV，按长表格式填好后拖进来；或者直接改 app.js 里的 SAMPLE_KEYS。
